# Report Template

Adapt the report to the selected analysis type. `[YEAR]` is the current calendar year. Do not include sections that are irrelevant to the selected type.

---

## Title

`[Game Name] — [YEAR] [Analysis Type] Report`

Examples: *RAID Shadow Legends — [YEAR] Negative Sentiment Report*, *... Update Feedback Report*, *... Bugs & Technical Issues Report*.

## Executive Summary

2 to 4 concise findings. Include the main finding, the biggest issue, the strongest evidence and the most important implication. Do not automatically mention spending.

## Objective

State the specific research question.

## Methodology

Include: data sources, time period, search keywords, number of discussions reviewed, number of relevant discussions, platforms reviewed, inclusion criteria, exclusion criteria, access limitations.

## Overall Findings

Present the most important findings.

## Sentiment Analysis

When applicable, report Positive, Neutral, Negative and Mixed. Include trends where evidence supports them.

## Top Issues

Rank the most important issues. For each: the issue, the evidence, frequency or strength, platforms, and why it matters.

## Evidence From Each Platform

Show direct evidence from the relevant platforms (see `evidence-rules.md` for the platform order and the wording when evidence is insufficient).

## Finding / Evidence / Source table — mandatory

Every final report contains this table, whatever the analysis type. The Source column holds a clickable direct source whenever possible.

| Finding | Evidence | Source |
|---|---|---|
| ... | ... | [direct link] |

## Analysis-specific section

Use the section that matches the type, and none of the others:

- Spending Impact
- Technical Issue Breakdown
- Update Reaction
- QoL Requests
- Monetization Feedback
- Competitive Balance
- Event Feedback
- Custom Analysis

## Business / Product Assessment

Include when useful. Assess severity, frequency, cross-platform confirmation, potential product impact and confidence. For non-spending analyses, do not invent revenue or spending implications.

## Recommendations

Recommendations must relate directly to the observed evidence. Examples: fix high-frequency bugs, prioritize repeated QoL requests, improve update communication, investigate balance concerns, review event design, address recurring monetization complaints, monitor emerging issues.

## Further Questions

Include only if unresolved questions could materially affect the conclusion.

## Caveats

Include the relevant limitations: access limits, indexing gaps, thin evidence, weak sources, anything that restricts how far the findings can be generalized.

---

## Final quality checklist

Before delivering, verify every item.

**Scope**
- [ ] Correct game
- [ ] Correct analysis type
- [ ] Primary evidence limited to the analysis period

**Sources**
- [ ] Reddit searched
- [ ] YouTube searched
- [ ] X/Twitter searched
- [ ] Web searched
- [ ] Facebook/Instagram checked when relevant
- [ ] User-provided links prioritized
- [ ] No-link fallback used when necessary

**Evidence**
- [ ] Findings are source-backed
- [ ] Direct URLs included
- [ ] Evidence is not duplicated
- [ ] Quotes are accurate
- [ ] Weak evidence is labeled
- [ ] Inaccessible content is not fabricated

**Analysis**
- [ ] Findings match the requested analysis type
- [ ] Sentiment is clearly classified where relevant
- [ ] Trends are supported by dated evidence
- [ ] Causality is not overstated

**Spending**
- [ ] Spending analysis NOT included unless requested
- [ ] If requested, explicit and indirect spending evidence are separated
