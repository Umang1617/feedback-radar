# Evidence Rules

How to collect, judge and word evidence. `[YEAR]` is the current calendar year.

## Evidence fields

For every meaningful finding, capture:

| Field | Requirement |
|---|---|
| Finding | Concise issue |
| Evidence | What the source says or shows |
| Source | Platform / source |
| Date | Publication date |
| Direct URL | Original source |
| Summary | Short explanation |
| Why it matters | Interpretation |
| Confidence | High / Medium / Low |

Optional fields: engagement (views, upvotes, comments, likes), cross-platform confirmation, issue category.

**Do not treat engagement as equivalent to sentiment prevalence.**

## Source detail format

For important evidence:

```
Direct Post: [Source name]
Date: [Date]
Platform: [Platform]
Summary: [Summary]
Why It Matters: [Interpretation]
URL: [Direct URL]
```

For spending analysis only, add: **Spending Impact:** Explicit / Indirect / None, and **Confidence:** High / Medium / Low.

## Source priority

Prefer, in this order:

1. Original community post
2. Original video
3. Original developer announcement
4. Official game source
5. Direct social-media source
6. Reputable gaming publication
7. Secondary reporting

Use secondary sources for context and corroboration. Prefer primary evidence.

## Source link requirement

Every material finding must have a source link. Prefer direct links to Reddit posts, YouTube videos, X/Twitter posts, Facebook posts, Instagram posts or reels, articles and official announcements. Do not link merely to a platform homepage when a direct URL is available.

## Sentiment classification

| Class | Meaning |
|---|---|
| Positive | Clear approval or satisfaction |
| Neutral | Informational or ambiguous |
| Negative | Clear criticism, frustration, dissatisfaction or rejection |
| Mixed | Meaningful positive and negative reactions |

Do not classify a source as negative merely because it discusses a problem.

## Issue clustering

Group individual complaints into themes. Possible themes: monetization, bugs, crashes, performance, balance, power creep, PvP, PvE, events, rewards, missing features, QoL, progression, matchmaking, characters, shards, energy, content drought, customer support, servers, UI/UX, FOMO, pay-to-win.

Add game-specific categories when appropriate. Never force an issue into an irrelevant category.

## Trend analysis

Where sufficient dated evidence exists, identify increasing, decreasing and stable complaints, sudden spikes, new issues, resolved issues, and sentiment changes after updates.

Use cautious language.

- Correct: *"Negative discussion increased following the update."*
- Incorrect: *"The update caused negative sentiment."* (unless causal evidence supports it)

## Deduplication

Do not count the same underlying discussion more than once. Deduplicate reposts, cross-platform copies, articles quoting the same post, videos discussing the same original incident, duplicate comments and syndicated articles.

Multiple **independent** sources discussing the same issue can be used as corroboration.

## Evidence quality

| Tier | What it looks like |
|---|---|
| **Tier 1 — Strong** | Primary source, direct player statement, clear date, clear context, multiple independent confirmations where available |
| **Tier 2 — Moderate** | Relevant primary discussion, some corroboration, reasonable context |
| **Tier 3 — Weak** | Single isolated complaint, ambiguous statement, low context, unclear date, or a secondary source |

Do not present Tier 3 evidence as proof of widespread community sentiment. Label weak evidence as weak.

## Representative quotes

Quotes may be included when useful. They must be from publicly accessible sources, accurate, concise, sourced, and dated where available. Never fabricate a quote and never turn a paraphrase into a quote.

Clearly distinguish a **direct quote** from a **summary of player feedback**.

## Google AI Overviews

AI Overviews may be used for discovery and context where available, but they are not automatically primary evidence. Whenever possible: identify the underlying source, open and review it, and cite the underlying article, post or video in the report.

## Sample size and generalization

The methodology should report total sources reviewed, relevant sources, sources by platform, unique findings and major themes.

Use: *"Among the publicly accessible discussions reviewed..."*

Do not claim *"Players generally believe..."* unless the evidence genuinely supports that level of generalization.

## Access limitations

If content is inaccessible, never invent it. State *"Source could not be independently accessed."* If another source confirms it, state *"Secondary evidence supports this claim."* If search indexing is incomplete, state *"Publicly indexed results were reviewed; platform access may limit completeness."*

## Platform-by-platform evidence

When sufficient evidence exists, organize it by: Reddit, YouTube, X / Twitter, Facebook, Instagram, Web / Articles.

Each important item includes the direct post or video, the date, a summary, the URL and why it matters.

If there is insufficient evidence for a platform, write: *"Insufficient publicly accessible evidence identified during the [YEAR] search period."*
